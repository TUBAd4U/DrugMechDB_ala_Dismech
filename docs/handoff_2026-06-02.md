## 1. Project overview

DrugMechDB is a curated knowledge graph of mechanistic paths from drugs to diseases, originally published in 2023. Each path is a directed Biolink-compliant graph: `Drug → intermediate biological entities → Disease`, with every edge carrying a typed predicate and a PubMed citation.

The v3 work (this PRD) layers an **agentic AI curation pipeline** over the existing 4,846-path corpus. The central problem v3 solves: **0 of 4,846 paths currently have evidence items.** Every edge in the legacy database asserts a relationship without citing a source. Closing this gap (the backfill workstream) plus enabling efficient new curation via a `/curate` slash command are the v3 deliverables.

### Architectural fundamentals

- **Format:** NetworkX `node_link_data` shape, serialized as YAML, validated by a LinkML schema, vocabulary-constrained by the Biolink Model.
- **Storage:** one path file per `kb/paths/{drugbank_id}_{disease_mesh}_{index}.yaml`. 4,846 files.
- **Schema:** `src/drugmechdb/schema/drugmechdb.yaml` defines `MechanisticPath` (tree_root), `PathNode`, `PathEdge`, `EvidenceItem`.
- **Predicate vocabulary:** 67-member `BiolinkPredicate` enum in `src/drugmechdb/schema/biolink_predicates.yaml`. All edge `key` values must be members.
- **Node ontology binding:** per node type, e.g. Drug → MESH/DrugBank, Protein → UniProt, BiologicalProcess → GO, ChemicalSubstance → MESH/CHEBI, Disease → MESH (full table in PRD §4.3 / AGENTS.md).
- **Evidence contract:** every `EvidenceItem.snippet` must be a verbatim substring of the cited PubMed abstract — no paraphrasing, no ellipses. This is the central hallucination defense.
- **Validation:** 4 layers via `scripts/qc.py` / `just qc`:
  1. LinkML schema (structure, required fields, types)
  2. Node ontology terms (via `linkml-term-validator`)
  3. Biolink predicate enum membership (`scripts/validate_predicates.py`)
  4. PubMed snippet-verbatim-in-cached-abstract (`scripts/validate_references.py`)
- **CI profile system:** `legacy` runs layers 1–3 only (for 4,846 evidence-free pre-existing paths); `ai_curated` runs all 4 and requires ≥1 evidence per edge. Profile is auto-detected from the file (any `evidence` field present → `ai_curated`) or set explicitly.

## 7. Architectural facts worth carrying forward

### 7.1 What the YAML format is based on

Three layered conventions:
1. **Container:** NetworkX `node_link_data` JSON format (`directed`, `multigraph`, `graph`, `nodes`, `links`). The legacy `parse.py` used `nx.read_yaml`; this is the dead giveaway. A path file is literally a `MultiDiGraph` waiting to be deserialized by `networkx.node_link_graph()`.
2. **Vocabulary:** Biolink Model (`https://w3id.org/biolink/vocab/`). Node `label` from `BiolinkNodeType` enum; edge `key` from `BiolinkPredicate` enum (67 values); node ID prefixes constrained per Biolink's node-type→ontology table.
3. **Meta-schema:** LinkML. Same toolchain as dismech. `tree_root: true` on `MechanisticPath`. Drives all four validation layers.

### 7.2 Relationship to the sibling dismech project

Both projects are Su Lab (UCSD), share the LinkML+verbatim-snippet+identical-`EvidenceItem` foundation, but diverge architecturally:

| | DrugMechDB | dismech |
|---|---|---|
| Domain unit | Drug→…→disease graph | One disease document |
| Document shape | NetworkX node-link | Flat document with ~46 top-level slots |
| Files in `kb/` | 4,846 path files | 691 disorder files + 148 history files |
| Typical file size | ~60 lines | ~1,000–1,500 lines |
| Edge system | One `PathEdge` primitive, 67 Biolink predicates, globally-resolvable CURIEs | Slot-as-predicate descriptors, `CausalEdge` with `causal_link_type` enum, local-name targets, `conforms_to` for module reuse |
| Skill ecosystem | 2 (`/curate`, `/backfill`) | 10+ (domain + subtask: cancer-curator, microbiome-curation, dismech-terms, dismech-references, dismech-compliance, etc.) |
| Research provider integration | First-class `BaseProvider` ABC; programmatic Anthropic + OpenAI SDK usage | External `deep-research-client` CLI orchestrating 5 non-Anthropic providers; regex-scraped citations |

### 7.3 The link-system design conclusion (don't re-litigate)

Previous session concluded: **DrugMechDB should keep its graph-shaped, typed-predicate, globally-CURIE-keyed edge system.** Adopting dismech-style document storage would be a regression on DrugMechDB's core graph-query use case. However, DrugMechDB should **selectively borrow** these dismech features as additive schema enrichments:
1. `causal_link_type` enum on `PathEdge` (DIRECT / INDIRECT_KNOWN_INTERMEDIATES / INDIRECT_UNKNOWN_INTERMEDIATES / UNKNOWN)
2. `hypothesis_groups` to express alternative mechanisms within one file
3. `curation_history` slot for explicit audit trail

These are deferred until Phase 4 is stable.
